# Chapter 02 Solutions

> ⚠️ **Spoiler alert:** These notes solve the Chapter 02 exercises. Skip if you want to discover your own answers.

1. Draw a doughnut plan with exploratory charters (e.g., checkout, security review) scheduled around releases, usability checks after UI tweaks, and security scans triggered by dependency changes.
2. For the last regression run, list three failure trends (e.g., flaky integration, timeout on reports, new assertion in legacy module) and propose owners or debugging pairs.
3. A release validation checklist can combine automation (unit, integration, contract) and manual observations (smoke notes, deployment status) tied to each product area.
4. Enumerate fixtures by layer (unit: generated objects, integration: schema snapshots, e2e: full data pipeline) and note the owner and refresh schedule.
5. A policy-as-code snippet could be a GitHub Actions gate that requires `lint` and `pytest --maxfail=1` to succeed before merging; document the logic in the checklist.
6. Pick a neglected doughnut activity (e.g., accessibility audit) and plan its next occurrence with owner, scope, and instrumentation.
7. Define a pyramid-health alert such as “integration coverage drops below 70%” and describe who gets paged and what they do (e.g., assign regression fix).
8. Run `python examples/ch02/pyramid_planner.py` to confirm the planner prints the expected layer counts; if needed, adjust dataset to match your service mix.
