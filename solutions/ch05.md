# Chapter 05 Solutions

> ⚠️ **Spoiler alert:** The following answers cover Chapter 05 exercises.

1. Draft a charter specifying gates (unit, regression, governance review) and owner (QA lead), e.g., “Payments depend on regression smoke + governance sign-off, QA owns triage.”
2. During the 15-minute review capture an action item per stakeholder: development (investigate flaky login), product (validate risk register entry), QA (update charters).
3. Add testing questions such as “Which suites cover this incident?” to incident templates so reviewers explicitly track automation coverage.
4. Schedule training with agenda and register attendees (developers, QA, product) noting hands-on time for the governance playbook.
5. Update the risk register entry by noting the current coverage, last review date, and the automation suites that guard the high-priority service.
6. Simulate escalation: trigger a failing regression gate, notify the owners via chatops, add the failure to war-room notes, and escalate to the platform team.
7. Pair with a teammate to write a narrative linking a KPI drop to a failed gate and include the next steps (quarantine, fix, retest).
8. Running `python examples/ch05/quality_review.py` returns a deterministic review summary; confirm the `actions` list contains `Assign debugging pair` when `has_failures = True`.
