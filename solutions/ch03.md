# Chapter 03 Solutions

> ⚠️ **Spoiler alert:** Chapter 03 solutions follow. Read only after you have attempted the exercises.

1. The pipeline stages are lint → unit → integration → regression; document which run on each trigger (push, PR, nightly) and their expected duration.
2. Three data-refresh strategies: (a) factory-based fixtures generated per test run, (b) containerized snapshots exported nightly, and (c) sanitized production dumps refreshed on schema change.
3. Sketch a dashboard with pass rates on the left, flaky-test counts below, and pipeline duration metrics that flag which stages can queue for retries to the right alongside owner names.
4. Describe rerun logic: capture failing job IDs, rerun the stage in isolation with identical environment variables, and funnel logs into a triage ticket.
5. The provided script `examples/ch03/solutions/seed_fixture.py` assembles deterministic fixture JSON and copies it to `solutions/fixtures/shared_fixture.json`, then prints the artifact path.
6. Metadata for alerts: stage name, duration, linked log URL, responsible owner, and `rerun_count` so responders know history.
7. Run `python examples/ch03/ci_pipeline.py` or `pytest examples/ch03` to confirm the pipeline definition still matches the YAML; adjust gating thresholds if durations change.
8. `examples/ch03/solutions/watchdog.py` inspects stage durations against budgets (5 min unit, 15 min integration) and prints warnings/alerts if thresholds exceed.
