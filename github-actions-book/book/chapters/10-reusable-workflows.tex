\chapter{Reusable workflows}

Reusable workflows are the right tool for cross-repo reuse.
They run as a normal workflow, but are invoked via \code{workflow\_call}.

\section{Defining a reusable workflow}
\begin{lstlisting}[language=YAML]
name: "CI: Python"
on:
  workflow_call:
    inputs:
      python-version:
        required: true
        type: string
    secrets:
      TOKEN:
        required: false

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ inputs.python-version }}
      - run: python -m pip install -r requirements.txt
      - run: pytest -q
\end{lstlisting}

\section{Calling it from another workflow}
\begin{lstlisting}[language=YAML]
jobs:
  ci:
    uses: org/repo/.github/workflows/ci-python.yml@v1
    with:
      python-version: "3.12"
    secrets:
      TOKEN: ${{ secrets.MY_TOKEN }}
\end{lstlisting}

\begin{patternbox}{Pattern: version reusable workflows with tags}
Pin to tags like \code{@v1} and keep backward compatibility within a major line.
If you pin to a branch, you trade stability for convenience.
\end{patternbox}
