\chapter{Supply chain security}

Your workflow depends on actions and packages you did not write.
Supply chain security is about minimizing that risk.

\section{Pin actions}
Use tags for convenience, but prefer commit SHAs for sensitive workflows.

\begin{lstlisting}[language=YAML]
- uses: actions/checkout@v4
# safer but more maintenance:
# - uses: actions/checkout@<commit-sha>
\end{lstlisting}

\section{Limit permissions}
Most workflows only need \code{contents: read}.
Give write permissions to a single job, not the whole workflow.

\section{Dependency scanning}
Automate updates with tools like Dependabot.
Treat action updates like dependency updates: review and test them.

\section{Restrict network access}
Self-hosted runners should use network policies and secrets isolation.
Avoid running untrusted pull requests on self-hosted runners.

\section{Provenance and attestations}
For critical releases, generate provenance or build attestations.
This improves traceability and strengthens the supply chain story.

\section{Action allowlists}
If your organization supports action allowlists, use them.
Restricting which actions can run reduces the attack surface.

\section{Update cadence}
Pin actions, but keep them updated.
Schedule dependency updates and review them like code changes.

\begin{warningbox}{Warning: third-party actions}
Every external action is a new dependency.
Only use actions you trust, and keep them updated.
\end{warningbox}

\begin{checklistbox}{Checklist: supply chain}
\begin{itemize}[nosep]
  \item Pin critical actions.
  \item Minimize permissions and secrets exposure.
  \item Separate untrusted PRs from privileged workflows.
\end{itemize}
\end{checklistbox}
