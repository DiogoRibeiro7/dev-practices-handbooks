\chapter{Permissions and secrets}

Security starts with the \code{permissions} block.
If you do not set it, GitHub applies defaults that may be too broad.

\section{The GITHUB\_TOKEN}
Every workflow receives a \code{GITHUB\_TOKEN}.
Set permissions at the workflow or job level.

\begin{lstlisting}[language=YAML]
permissions:
  contents: read
  pull-requests: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
\end{lstlisting}

\section{Job-level permissions}
You can narrow permissions for specific jobs.
This is useful when a single job needs write access.

\begin{lstlisting}[language=YAML]
jobs:
  publish:
    permissions:
      contents: write
    runs-on: ubuntu-latest
    steps:
      - run: ./scripts/publish
\end{lstlisting}

\section{Secrets}
Secrets are encrypted values stored in GitHub.
Use them via the \code{secrets} context.

\begin{lstlisting}[language=YAML]
- name: Deploy
  env:
    API_TOKEN: ${{ secrets.API_TOKEN }}
  run: ./scripts/deploy
\end{lstlisting}

\section{Environment protection}
Use environments to add approvals and separate secrets for staging and production.
The environment name can be set per job.

\begin{lstlisting}[language=YAML]
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - run: ./scripts/deploy
\end{lstlisting}

\section{Least privilege patterns}
Start with \code{contents: read} and add only what you need.
Separate risky jobs into a dedicated workflow when possible.

\section{Forked pull requests}
Secrets are not exposed to workflows triggered by forks by default.
Design your PR workflows so they can run without secrets.

\section{Secret rotation}
Rotate secrets regularly and automate the rollout.
Use environment-scoped secrets so production values stay isolated.

\begin{warningbox}{Warning: secrets in logs}
Do not echo secrets.
GitHub masks secrets, but it is safer to avoid printing them entirely.
\end{warningbox}

\begin{checklistbox}{Checklist: permissions and secrets}
\begin{itemize}[nosep]
  \item Define \code{permissions} explicitly.
  \item Use job-level permissions for write access.
  \item Scope secrets to environments.
  \item Avoid running privileged jobs on untrusted PRs.
\end{itemize}
\end{checklistbox}
