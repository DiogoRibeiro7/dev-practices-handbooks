\chapter{Permissions and secrets}

Most incidents with Actions are not “CI problems”.
They are permission problems.

\section{GITHUB\_TOKEN permissions}
Set permissions explicitly.
Default permissions can be broader than you need.

\begin{lstlisting}[language=YAML]
permissions:
  contents: read
\end{lstlisting}

If you need to create releases:
\begin{lstlisting}[language=YAML]
permissions:
  contents: write
\end{lstlisting}

\section{Secrets}
Secrets are injected as environment variables or passed in \code{with:}.
Treat them as sensitive in logs.

\begin{lstlisting}[language=YAML]
- name: Use secret
  env:
    API_TOKEN: ${{ secrets.API_TOKEN }}
  run: |
    test -n "$API_TOKEN"
\end{lstlisting}

\section{Environments}
Environments allow:
\begin{itemize}[nosep]
  \item protection rules
  \item required reviewers
  \item environment-scoped secrets
\end{itemize}

\begin{warningbox}{Warning: secrets in PRs}
Forked PRs do not receive secrets.
Design your workflows so PR checks do not depend on secrets.
\end{warningbox}

\begin{checklistbox}{Checklist: least privilege}
\begin{itemize}[nosep]
  \item Set \code{permissions} at workflow level.
  \item Elevate permissions only in jobs that need it.
  \item Avoid \code{pull\_request\_target} for code execution.
\end{itemize}
\end{checklistbox}
