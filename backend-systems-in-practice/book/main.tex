\chapter*{Preface}
This book is about building backends that are easy to change and safe to operate.
It is written for engineers who want to ship services and keep them healthy in production.

The approach is opinionated:
\begin{itemize}
  \item keep business logic out of frameworks
  \item design APIs for change
  \item treat data as a first-class interface
  \item measure what matters (latency, errors, saturation)
  \item keep security and reliability in the default path
\end{itemize}

\chapter*{Closing note}
Backends are systems.
Code quality matters, but the system behaviour matters more.
Make tradeoffs explicit, keep interfaces stable, and build feedback loops into the product.
