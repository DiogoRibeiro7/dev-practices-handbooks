\chapter{Event-driven systems}

Event-driven systems decouple producers and consumers.
They can scale well, but they require discipline in schema and delivery guarantees.

\section{Events and commands}
Events describe something that happened.
Commands request something to happen.
Keep them distinct.

\section{Schemas}
Define event schemas and version them.
Use a schema registry if you have multiple consumers.

\section{Ordering and duplication}
Assume events can arrive out of order and more than once.
Design handlers to be idempotent.

\section{Backpressure}
Consumers must handle overload gracefully.
Use queue limits and retry policies.

\begin{checklistbox}{Checklist: event-driven}
\begin{itemize}[nosep]
  \item Version event schemas.
  \item Design idempotent consumers.
  \item Expect reordering and duplication.
\end{itemize}
\end{checklistbox}
