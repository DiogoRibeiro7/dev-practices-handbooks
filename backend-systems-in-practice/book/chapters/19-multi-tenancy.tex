\chapter{Multi-tenancy}

Multi-tenant systems serve multiple customers from one codebase.
The design choice is how much isolation each tenant receives.

\section{Isolation models}
\begin{itemize}[nosep]
  \item shared database, shared schema
  \item shared database, separate schema
  \item separate databases per tenant
\end{itemize}

\section{Tenant identification}
Every request should carry a tenant identifier.
Never infer tenant from user data alone.

\section{Data access rules}
Enforce tenant scoping in every query.
Prefer database-level row security when possible.

\section{Noisy neighbors}
Large tenants can degrade others.
Use quotas and rate limits to protect shared resources.

\begin{checklistbox}{Checklist: multi-tenancy}
\begin{itemize}[nosep]
  \item Decide isolation level early.
  \item Enforce tenant scoping everywhere.
  \item Protect against noisy neighbors.
\end{itemize}
\end{checklistbox}
