\section{Roadmaps and Commitments: Outcomes vs Features}
A roadmap is a decision tool, not a contract. Outcome roadmaps track the change you want in the world; feature roadmaps track deliverables. You need both, but never confuse them.

\subsection{Jira setup steps (roadmaps)}
\begin{enumerate}
  \item Use Initiatives (Advanced Roadmaps) for outcomes; Epics for features.
  \item Link Epics to Initiatives with “implements” or parent-child.
  \item Use Target Release for feature commitments; use OKR Link for outcomes.
  \item Create two views: Outcome Roadmap (Initiatives) and Feature Roadmap (Epics).
\end{enumerate}

\subsection{How to avoid roadmap as contract}
Use time ranges and confidence, not exact dates. Track dependencies and risk for every committed Epic. Communicate changes as trade-offs, not surprises.

\subsection{Worked scenario: roadmap negotiation}
An exec asks for a specific feature by end of quarter. The PM shows the Outcome Roadmap and explains the trade-off: delivering the feature will delay a retention outcome. The decision is recorded in the Epic with updated Target Release and Risk.

\subsection{Case study insert}
INIT-2 is the outcome roadmap item, while EPIC-4 and EPIC-5 are feature commitments. The team communicates R1 as a range, not a fixed promise.
\subsection{Checklist}
\begin{itemize}
  \item Initiatives represent outcomes; Epics represent deliverables.
  \item Commitments include confidence level and dependencies.
  \item Outcome roadmap is reviewed monthly, feature roadmap biweekly.
  \item Changes are logged as trade-offs.
  \item Roadmap communication uses ranges, not fixed dates.
\end{itemize}

\subsection{Failure modes and fixes}
\begin{enumerate}
  \item \textbf{Failure:} Roadmap is treated as a promise. \textbf{Fix:} Use ranges and confidence levels.
  \item \textbf{Failure:} Outcomes are tracked as features. \textbf{Fix:} Separate Initiatives from Epics.
  \item \textbf{Failure:} Dependencies are hidden. \textbf{Fix:} Require dependency links for commitments.
  \item \textbf{Failure:} Reviews are ad hoc. \textbf{Fix:} Set fixed roadmap review cadence.
  \item \textbf{Failure:} Changes are not recorded. \textbf{Fix:} Document trade-offs in the issue.
\end{enumerate}
